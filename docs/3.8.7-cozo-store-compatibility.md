# 3.8.7 Cozo store compatibility hotfix

## Incident

A clean upgrade from SuperLocalMemory 3.8.5 to 3.8.6 on macOS preserved
`memory.db` but failed to start the daemon when opening the existing Cozo graph:

```text
pyo3_runtime.PanicException: Unknown storage version 1
left: 1
right: 3
```

The 3.8.6 package changed `pycozo[embedded]` from 0.3.0 to 0.7.6 without a
store-format migration. Reinstalling the established 0.3.0 dependency opened
the same graph successfully. SQLite `PRAGMA quick_check` remained `ok`, and
the pre-upgrade memory, fact, entity, edge, and profile counts were unchanged.

## Plan

1. Add a release guard that requires the core, `cozo`, and `scale` dependency
   surfaces to retain the store-compatible PyCozo 0.3.0 pin.
2. Revert only the PyCozo dependency and lockfile entries.
3. Contain PyO3 native store panics at the optional Cozo boundary so a graph
   created briefly by 3.8.6 cannot prevent canonical SQLite startup.
4. Bump all public package and generated-plugin surfaces to 3.8.7.
5. Run the focused dependency, Cozo adapter, packaging, plugin, and exact
   artifact gates.
6. Clean-install the candidate on the real macOS store and verify daemon
   readiness, database integrity, version, and preserved counts.

No graph rebuild, deletion, or in-place storage rewrite is allowed.
