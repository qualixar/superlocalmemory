# Dashboard Tour

The dashboard is a local web page served by the SLM daemon. Run `slm dashboard` to open it; it listens on port 8765 by default (`slm dashboard --port` to change it, and the same port the daemon uses for everything else). The left sidebar has 19 panes in six groups: Overview, Memory, Intelligence, System, Integrations and Config. This page walks through every pane in sidebar order, says what you will see, and points to the wiki page that explains the idea behind it. Nothing here needs a cloud account; the only panes that talk to the internet are Connected apps and Cloud Backup, and both are off until you turn them on.

A few things hold across the whole dashboard. A profile selector sits at the bottom of the sidebar and switches the memory namespace every pane reads from ([Profiles](Profiles)). Changes that need a daemon restart say so next to the control. And some features have no pane at all: restore points are CLI and API only, reviewing a proposed correction is `slm review-correction` or the MCP tool, and the active MCP profile can be seen but not changed from the dashboard.

## Overview

**Answer Check** is the first item and carries a "new" tag. It shows which answer check is running (on this Mac, online with Jev, or off), a "Try it" box, how often recall said it had nothing that answers the question, how long checks took against the 3-second limit, and a list of recent checks. Setup and consent for the online option live here and in Settings. Explained in [Answer Check](Answer-Check).

**Dashboard** is the home pane: "Your memory, at a glance" with four counters (memories, facts, graph nodes, edges), a memory activity chart, a system card, recent activity, and "Where memories come from". A dismissible what's-new card appears after upgrades, and under it a **What memory can do now** card with one line for each new thing that is not turned on yet (memory on every prompt, reminders on cues, what SuperLocalMemory measures, where a memory came from, held back from instructions, secrets stored as placeholders, signed memories, why was this shown, proposed changes), each with a link; a feature you turn on drops out of the list. When something needs your answer, a **Needs your answer** card appears at the top of the right column: two memories that disagree about the same thing (each with the date it was said, and **Keep this one**, **Both are true**, **They are about different things** or **Not sure**), and memories whose source file changed or is gone (**Still true** once you have looked at the file). Agents answer the same questions with the `settle_dispute` tool and the terminal with `slm disputes`; the card hides itself when nothing is waiting. A **Help it get things right** card asks, one at a time, the questions SuperLocalMemory's judges were asked about pairs of memories, without showing their answers; answers are how a judge earns permission to act on its own, and an agent may give them too (`slm audit --answer`, or the `settle_dispute` tool), counted only when its model differs from the judged one. The terminal has the same questions in `slm audit`. A **Proposed changes** card lists changes SuperLocalMemory suggests to your memory, such as retiring an older memory or rewriting a summary, in plain words: **Apply** makes all of a set at once, **Reject** changes nothing, and **Undo** on a set you applied puts back exactly what it replaced; the terminal has `slm proposals`, and agents cannot decide a set for you. A **Living wiki** card appears once there are pages, or once the Markdown wiki is switched on: pages SuperLocalMemory compiled from your memories (the current state of a subject, how a group of decisions went, what is known about a topic). Every sentence is a word-for-word piece of a memory it cites, or a fixed template over its values, and no model wrote any of it; **Read** shows each sentence with **Open memory**, which takes you to that memory, and says how many sentences were left out and why. **Rebuild pages** compiles them again and approves them as you; **Read my edits** (while the Markdown wiki is on) turns what you changed in the Markdown files into proposals that wait under **Proposed changes**, and a line you delete forgets nothing. The terminal has `slm wiki`; the full guide is `docs/living-wiki.md` in the repository. A **Held back from instructions** card appears once the instruction firewall is switched on (or in shadow): memories that asked to be a pin, a standing rule or part of your core memory but did not come from you (a tool's output, a web page, an agent's own words, or anything saved before 4.2.30 and not already a pin or rule), each with where it came from and what it asked for; **Promote** lets that one be an instruction, **Promote all** clears the list, and agents and the terminal do the same with `slm trust promote` or the `core_memory` tool. Nothing waits for you: any caller may promote, and each promotion is recorded and can be withdrawn. A **Recent decisions by your agents** card lists who decided what (a promotion, a settled dispute, an applied or rolled-back set of proposed changes, a blind audit label), through which channel and when, each with an **Undo**; Memory Health counts them in one line. It stays hidden until something has been decided. For how those counts come to be see [How Remember Works](How-Remember-Works).

**Brain** carries a "live" tag and has five tabs: Overview, Reward signal, Behaviour, Connected clients and Source quality. It is a read-only picture of what SLM has learned and observed, including which agents are connected and how trustworthy each source has been. Explained in [Living Brain](Living-Brain).

## Memory

**Knowledge Graph** draws your memory as a force-directed graph in three tiers (communities, entities, episodes) with a node inspector, quick-insight chips such as "Changed This Week" and "Contradictions", and an "Ask your memory" chat. Explained in [Knowledge Graph and Entities](Knowledge-Graph-and-Entities).

**Memories** is headed "Everything you've remembered" and has six tabs: Recall Lab, Summaries, Saved views, All memories, Creation timeline and Knowledge clusters. The search box has a **Show closest matches** option, and an empty search says why instead of "No results found." The Recall Lab runs a query and shows each retrieval channel's status and score, which is the fastest way to see why something was or was not found ([How Recall Works](How-Recall-Works)). Memory kinds show up here as badges and a filter ([Memory Kinds](Memory-Kinds)). Bookkeeping entries such as a receipt id or a session-ended line carry a **stub** badge: kept and listed, but never used as an answer ([Health and Repair](Health-and-Repair)). Opening a memory shows **Where this came from** (you said this, an agent's own words, a tool's output, a web page, an imported file, written by a model, or unknown for memories saved before 4.2.30) and, when it fills a slot, **When it was true**: the value it states, the values over time with their start dates (shown now, replaced, in question), any open dispute with the same one-click answers as the home card, and whether its source file changed. On request it also answers **Why was this shown?**: where the memory came from and why that counts, whether the instruction firewall holds it back and who approved it, whether its signature still matches (signed memories, `trust.signing`), and the last times an agent was shown it with the reason for each. The terminal has `slm why`.

**Entity Explorer** lists canonical entities (people, organisations, concepts, events) with a type filter and a temporal timeline for the selected entity. Explained in [Knowledge Graph and Entities](Knowledge-Graph-and-Entities).

**Multi-Agent Memory** shows which agent wrote what: an agent activity table and the recent memories each one saved, refreshed about every 15 seconds, with an adapter guide when nothing has connected yet. Explained in [Multi-Agent Memory](Multi-Agent-Memory).

**Documents & Images** carries a "new" tag. Until you turn the feature on it shows a turn-on card; afterwards it has "Add images or PDFs", a Documents list, and a Folders section for connecting a folder or Obsidian vault read-only. Explained in [Pictures and Documents](Pictures-and-Documents).

## Intelligence

**Skill Evolution** has a counter strip (skill events, unique skills, performance assertions, skill correlations), a lineage graph of how a skill changed over versions, an "Evolution engine" card with the on and off switch and a button to run one cycle, and a skill performance table. Evolution is off by default and every proposed change waits for your approval. Explained in [Skill Evolution](Skill-Evolution).

## System

**Health** opens on a status strip (daemon, memory database, math layers, mesh broker) and continues with math-layer health, trust signals, connected agents, a "Memory health" card (automatic description of older memories, repairs that wait for your Fix button, and Undo) that also holds the "Memory store" check run once per upgrade with its Repair button, and a component list with "Retry now". Explained in [Health and Repair](Health-and-Repair); problems and fixes are in [Troubleshooting](Troubleshooting). A **Truth checks** card runs the same read-only checks as `slm doctor --truth` when you press **Run checks**, and says each result in plain words, including whether signed memories still match their signatures and whether the audit log is intact. A **Shown to your agents** card (press **Show**) lists what your agents were recently given, grouped by conversation: at the start of a conversation, with a prompt, on a cue, or when an agent asked. Each memory says how it was chosen, whether it is still current, disputed or from a file that changed, and how old it is; two numbers sit beside it: how many prompts did not need memory and so were skipped (the rules skip a prompt that needed memory at most 10% of the time, and the score skips nothing until the prompts that needed memory add up to enough weight, 180, so a young store shows no score skips), and how many memories the harm check would withhold. The harm check only watches and nothing is withheld; it tests a memory only when your agents got it in some sessions and went without it in others (a randomised check), and until a memory has had both it says "Not testable yet: no memory has been left out often enough to compare" rather than claiming none made an agent worse. A **Trust overview** card (press **Check now**) counts your memories by where they came from, says how many wait for your OK (with a link to that card), whether signed memories are intact, whether credentials are held as placeholders, and whether the audit log is intact. A **What memory did for you** card (press **Show**) gives the same report as `slm health --memory`: how often your agents were given memories, how often they acted on them, which memories are used most and which rarely, and whether memory measurably helps (it says "Helps" or "Hurts" only when the evidence is clear however often you look), and whether each part of SLM's learning is still learning, stalled, switched off, waiting for agents or not connected.

**Governance** groups five tabs and states plainly that nothing in it is read-only: Lifecycle (active, warm, cold and archived memories and compaction), Access & Users (roles and company mode), Trust (per-agent and per-fact trust), Compliance (retention rules, erasure, the tamper-evident audit trail) and Ingestion (the Gmail, Calendar and transcript adapters). Admins also get an "Admin: Ops Health" tab for failed operations. Explained in [Governance](Governance), [Security, Company Mode and Teams](Security-Company-Mode-and-Teams) and [Ingestion Adapters](Ingestion-Adapters).

**Optimize** shows the caching and compression switches, headline savings, a savings-by-provider table and a 24-hour hit and miss chart. Explained in [Optimize](Optimize).

## Integrations

**MCP & Tools** (headed "MCP & Integrations") shows the active tool profile, the available profiles with their tool counts, and instructions for changing profile; it cannot change it for you. See [MCP Tools](MCP-Tools).

**Connected apps** carries an "Optional" tag. It has four parts: This computer, Your connected apps, Add an app, and technical details. It is where you let ChatGPT, Claude on the web and other web apps reach this computer's memory through the hosted gateway, per app and per permission. Explained in [Web Access and Connected Apps](Web-Access-and-Connected-Apps) and [Privacy and Data Flow](Privacy-and-Data-Flow).

**Mesh Peers** lists the agent sessions and connected apps that can see each other, with a send box and recent mesh activity. **Bot messages** (tagged "new") lists what other bots sent, and lets you mute, rename or retire a peer. Both are explained in [Bots That Talk](Bots-That-Talk).

**Bounded Loops** shows whether the Bounded Loops bridge is installed, how the loop works, how to run one from the CLI or MCP, and the framework adapters. An uninstalled bridge is reported as simply "not installed". Explained in [Bounded Loops](Bounded-Loops) and [Framework Adapters](Framework-Adapters).

## Config

**Settings** is searchable ("Search every setting...") and groups everything configurable into sixteen sections, each noting whether a restart is needed: operating mode and LLM provider, answer check, embeddings and retrieval (including the memory-engine card, shown only for a store whose text an older release moved), storage backends, memory scope, recall and memory behaviour, auto-capture, auto-recall, auto-invoke, the forgetting engine, skill evolution, backup, mesh network, trust and source quality, rate limits, and the daemon (ports and idle timeout). A sticky footer has "Save all changes" and "Discard". Memory scope and Recall & memory behaviour save as you change them, and rate limits apply immediately. Reference: [Configuration](Configuration), [Modes Explained](Modes-Explained) and [Embedding Models](Embedding-Models).

**Cloud Backup** is headed "Backup & cloud sync": a status hero, an encryption card, counters, connections to GitHub or Google Drive, a scope selector and a history. Backups are encrypted on this computer before upload. Explained in [Cloud Backup](Cloud-Backup).

## Which pane answers which question

| You want to know | Open |
|---|---|
| Why did recall miss something? | Memories > Recall Lab |
| Which agent saved this? | Multi-Agent Memory |
| Is anything broken right now? | Health |
| What did SLM just learn from my sessions? | Brain |
| Can I trust this answer? | Answer Check |
| Who can read or change memory? | Governance > Access & Users |
| How many tokens did I save? | Optimize |
| Which apps can reach my memory from the web? | Connected apps |

Code: `src/superlocalmemory/ui/index.html`, `ui/js/od-shell.js` (the sidebar model), and one `od-*.js` renderer per pane; routes under `server/routes/`.
